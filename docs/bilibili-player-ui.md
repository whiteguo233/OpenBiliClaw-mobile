# 哔哩哔哩播放页

页面采用移动端播放页常见的层级：黑色播放器 → 固定“简介 / 评论”标签 → 独立滚动内容。视觉参考入口为 [哔哩哔哩官方 App](https://apps.apple.com/cn/app/id736536022)。只呈现客户端已接入的能力。

- 简介：UP 主和关注 → 可展开标题、播放量、弹幕量、发布时间、正文 → 点赞、投币、收藏、分享 → 选集 → 推荐理由 → 相关推荐。
- 评论：评论总量和热度说明 → 评论及回复预览 → 固定评论输入框。加载状态、空列表和失败重试分别展示；滚动接近底部自动加载下一页，失败后手动重试。
- 播放器：返回和更多按钮覆盖在画面上。弹幕开关、弹幕设置紧邻标签；清晰度、倍速、字幕、全屏继续使用现有播放器。
- 更多：稍后再看、一键三连、播放设置、网页版播放、B 站 App 跳转。点赞支持长按三连。

主题使用中性浅色 / 深色内容表面和粉色选中态。标题、评论和元数据使用系统字体缩放。播放器在竖屏查看评论、滚动简介或键盘展开时让出空间。标签切换保留草稿和滚动位置，不重新请求播放流。打开相关推荐会暂停当前视频，返回时恢复原有播放状态。

API 路径、认证和 Cookie 处理沿用现有协议。相关视频的 `duration` 与 `stat.danmaku` 为可选展示字段，旧后端缺少这些字段时不显示对应内容。

## 真实后端端到端测试

```bash
flutter drive --no-pub -d DEVICE_ID \
  --driver test_driver/bilibili_player_live.dart \
  --target integration_test/bilibili_player_live_e2e_test.dart \
  --dart-define=BILIBILI_E2E_BASE_URL=http://127.0.0.1:18420
```

地址通过编译参数传入，不覆盖应用保存的连接配置。iOS 模拟器可访问宿主机 loopback；其他设备应填入实际可达地址。测试后端需要已有可用的 B 站登录状态。

该脚本使用系统实际 HTTP 客户端、B 站 CDN 视频与音轨、真实评论和弹幕。播放器必须解码出画面尺寸，并在加载完成后继续播放超过三秒才算成功。它验证竖屏、浅色与深色、倍速、简介与评论切换、回复与键盘、草稿、评论翻页、全屏评论、相关推荐跳转及返回、课程分集和实际解码画质切换。

测试只读取账号数据和在本机编辑未发送的草稿，不发布评论、不关注、不点赞、不投币。`build/player-live/` 保存实际页面截图和 `report.json`；请求记录只保留路径、状态码、耗时，以及公开的视频 / 分集标识，不写入 Cookie、响应内容或带签名的流地址。测试会像正常播放一样更新模拟器内的播放进度。

### 2026-09-30 真实环境发现与修复

连接已有 `127.0.0.1:18420` 后端，B 站登录状态为 `logged_in`。iPhone 17 Pro 模拟器运行 iOS 26.5；此次没有连接可用的物理手机，不代表真机蜂窝网络或 Tailscale 链路验收。

真实画质切换暴露了后端问题：`BV1Eb411u7Fw` 的第 2 集请求 `qn=32`，实际返回 `qn=80`、1912×1080。上游候选包含 850×480 的 AVC 流，但旧代码只按编码格式选择首条候选，未匹配 `qn`。

后端修复基于 `b66030ab` 验证：`get_play_info` 先匹配画质，再在该画质内选择编码；目标画质不可用时保留原有回退行为。后端模块文档与变更日志同步更新，补充四种多画质 / 多编码回归情况。

运行中的测试实例已迁移到经过验证的固定源码快照 `8911d43d`，不再依赖临时开发 worktree；保留原有配置、数据库和账号凭据。启动配置备份及运行路径只保存在部署机器的私有目录中。
